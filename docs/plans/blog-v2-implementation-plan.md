## 1. V1 Invariants (the hard gates every PR is regression-tested against)

These are the non-negotiable properties carried from the ledger, restated as concrete, regression-gated assertions. Every phase PR keeps them green in CI.

1. **The 6 live posts keep their URLs, content, categories/tags, and bylines.** URLs and `data.body` are untouched (ADR-009: markdown storage = no format conversion). Categories/tags are preserved on edit (Phase-1 PR0 prerequisite — V1 stores but does not preserve them on the upsert path, see §2). Bylines render each row's `data.author` string through the new author resolver via the legacy fallback (R4-F9, §2). Any `mailto:`/`tel:`/site-relative body links survive (sanitizer policy, invariant #3).
2. **Draft invisibility.** Draft, scheduled, and archived posts are invisible on every public surface. The live read filter is an exact-match `WHERE status = 'published'` (`content.ts:81,103`); Phase 2 hardens this with a DB `CHECK` constraint (R4-F2, §11 Phase 2).
3. **Sanitizer rigor equivalent-or-stronger.** The frozen `marked` → `DOMPurify.sanitize(STRICT_CONFIG)` → `.blog-body` pipeline (`renderPostBody`, `blog-content.ts:364`) is preserved verbatim. The four `STRICT_CONFIG` properties re-asserted in CI (`blog-content.ts:425-428`): (a) **no `id`** — `ALLOWED_ATTR` is `href`/`src`/`alt`/`title` only; (b) **fragments stripped**; (c) **body URI policy** `ALLOWED_URI_REGEXP = /^(?:https:|mailto:|tel:|\/(?![/\\]))/i` — `https:`/`mailto:`/`tel:`/site-relative allowed, **NOT "HTTPS-only"** (tightening to https-only is FORBIDDEN — it breaks live posts' mailto/tel links, R3-F1); (d) `ALLOW_DATA_ATTR` and `ALLOW_ARIA_ATTR` both `false`. The featured-image `IMAGE_SCHEME_REGEX` (`blog-content.ts:45`, `/^(\/(?![/\\])|https:\/\/)/`) is a DISTINCT, stricter validator and must not be reused for body links or ticker hrefs.
   - **Latent constraint (R2-F4, deferred):** `collectBodyImageAlts` (`blog-content.ts:253`) walks markdown `image` tokens only. Under Option-B pure-markdown storage this fully covers V1, TipTap-markdown round-trip, the source toggle, and AI body output. A raw inline `<img>` in `data.body` would render (DOMPurify allows `img`) but bypass the alt-quality gate. No current path admits raw `<img>`; any future HTML escape hatch MUST add an HTML-aware alt gate first (recorded §5).
4. **Cache staleness ≤5 min, preserved-or-improved-with-rationale.** Collections cache at `DEFAULT_COLLECTION_TTL = 5 min` (`content.ts:28`); `settings` caches at `SETTINGS_TTL = 30 min` (`content.ts:29`). Ticker + virtual-author keys live in `settings`, so a 5-min special-case read path is added (R4-F11, §10/§11 Phase 6) so they are not 6× staler than the analogous AnnouncementBar 5-min strip.
5. **Supervised rollout boundary.** Agents never mutate prod; every merge to main auto-deploys; the owner supervises merges; per-step stacked PRs within a phase; an owner checkpoint between phases.
6. **Gates green per PR:** `lint --max-warnings=0` + typecheck + full vitest + `format:check` + build. Run single test files during dev; full suite before commit.

## 2. Canonical Schema & Field-Mapping Table

Blog posts remain rows in the existing `content` table with `type='blog'` — **no new tables** for posts. The `content` table has real columns `slug`, `type`, `title`, `data` (JSONB), `status`, `created_at`, `updated_at`, `author_email`, `id` (`content.ts:79`), upserted by `INSERT INTO content (...) ON CONFLICT (type, slug) DO UPDATE` (`app/src/pages/api/admin/content.ts:577-590`). **`body` is NOT a column — it lives in `data.body`** (R2-F13). A build agent must never add a `body`/`canonicalUrl`/`reading_time` column.

## 4. Cross-Cutting Architecture Notes

- **One render path.** TipTap, the markdown-source toggle, AI body output, the importer, and the 6 legacy posts all emit the same markdown rendered by the one frozen `renderPostBody` pipeline. There is no second render path to audit.
- **Shared Layout `<head>` extension (Phases 3+4).** A per-page `robots`/`noIndex` prop on `Layout.astro` and a `noindex, follow` third state in `resolveSeoMetadata` (driving BOTH `meta[name=robots]` at `Layout.astro:65` AND the conditional `meta[name=googlebot]` at `Layout.astro:66`), plus a JSON-LD/`<head>` slot for per-post structured data and RSS auto-discovery. This is one cross-cutting Layout+seo-config extension shared by Phase 3 (robots third state) and Phase 4 (JSON-LD/RSS link).
- **Canonical resolver reality.** `resolveSeoMetadata` strips the query string (`normalizePathname` → `withoutHash.split('?')`, `seo-config.ts:146`) and builds `new URL(normalizedPath, siteOrigin)`. Category index pages MUST therefore be PATH segments `/blog/category/[slug]` — a query-param shape would collapse every category canonical to `/blog` and break the ≥2-member design (R4-F15).
- **Auth fixture.** The required authenticated-browser Playwright fixture bootstraps via `context.addCookies` with `name:'sbms-admin-session'` and exact attributes matching the live session cookie (`auth/callback.astro:73-77`: path '/', httpOnly true, sameSite 'lax', secure on HTTPS). V1's only authed-E2E precedent uses a request-context Cookie header that bypasses cookie-attribute matching and does NOT prove page-level auth — hence the explicit PR2 spike (R4-F22).

## 5. Storage & Editor (Phase 1) — Option B / Markdown Round-Trip (ADR-009, ACCEPTED)

The TipTap storage fork is **resolved in ADR-009: TipTap as the editor with Markdown round-trip storage (Option B).** Post bodies stay markdown in `data.body`. On load `MarkdownManager.parse` hydrates the document; on save `MarkdownManager.serialize` writes markdown back. The frozen render pipeline is preserved verbatim. Summary of the binding decisions (full rationale in ADR-009):

- **No format conversion of the 6 live posts** — `data.body` stays markdown; URLs/content untouched. The only fidelity risk is open-and-save round-trip, gated by a byte-identical canary (all 6 posts run through `parse → serialize` in CI, view-less).
- **Lossless-by-construction extension set.** The extension set is restricted to constructs `@tiptap/markdown` (v3.24.0, CommonMark/MarkedJS-backed) round-trips cleanly. **Underline and text-align are DROPPED** from the toolbar (markdown-non-serializable). Non-serializable typography input rules are disabled. Tables stay authorable only via a markdown-source toggle unless a clean round-trip is proven.
- **Faithful preview** re-renders through the real `.blog-body` pipeline (`renderPostBody`), NOT the editor canvas and NOT `.prose` (`@tailwindcss/typography` is not installed; `.prose` is unstyled here — R3-F11).
- **Sanitizer frozen.** Because the render pipeline is unchanged, the four `STRICT_CONFIG` properties (§1 invariant #3) hold by construction and are re-asserted in CI via the standalone `MarkdownManager` XSS matrix.
- **Contingency (PR2 headless spike).** Adoption of the view-less round-trip as the per-PR CI gate is contingent on the PR2 headless spike: one of the 6 live posts must pass `parse → serialize` byte-identical (or documented normalization) in jsdom with NO `EditorView`. If the spike fails, the fallback is to keep V1's markdown textarea as the body surface and layer TipTap's chrome onto it — NOT escalate to HTML storage (which would reopen the sanitizer audit through a new ADR).
- **Latent alt-gate constraint (R2-F4).** Recorded in §1 invariant #4: any future HTML escape hatch into `data.body` must add an HTML-aware alt gate before raw `<img>` is permitted.

## 6. AI Writing & Voice System (Phase 7) — ADR-010 (NEW, authored in Phase 7)

The AI subsystem is the LAST phase, key-optional by design, with its own ADR-010. Full security/cost/latency criteria are enumerated in §11 Phase 7; this is the architecture summary.

- **Key-optional.** The Anthropic key is stored in a NEW `admin_settings` table (`is_sensitive=true`), encrypted at rest by a NEW `crypto.ts` (AES-256-GCM, per-encryption random IV + auth tag, fail-closed). Decrypted only at request time in memory. `isAiConfigured` returns a boolean only — never key material. When no key is configured, every AI route 404s and every AI affordance is hidden.
- **Default = synchronous Sonnet.** The DEFAULT generation tier is Sonnet 4.6, synchronous — all actions complete inside the confirmed Netlify timeout; NO `ai_jobs` table, NO background function, NO poll endpoint, NO polling UI. The Opus 4.8 async subsystem (202 → `ai_jobs` → poll) is built ONLY if the owner explicitly opts in OR if the tier confirmation forces the `draft` action async (R3-F14/R4-F6). **Per-action `max_tokens` ceilings** (inline ~512, excerpt/headline ~256, draft 1500-2000) are the only per-action hard backstop on output-rate billing.
- **Three modes** (per the old spec §7): (1) in-editor selection toolbar (rewrite/simplify/shorten/expand/tone); (2) panel whole-post actions (headline, excerpt, first draft, category/tag suggestions); (3) per-field SEO AI. All flow through one internal service that prepends the voice config as data-delimited context and routes through `validateBlogData` + `renderPostBody` (no privileged write path).
- **Voice system** in `admin_settings`: reference corpus (curated seed; auto-add opt-in), plain-language Style Profile (NOT raw scores, R2-F18), anti-pattern blocklist (enforced IN-PROMPT on the single generation, NOT a second corrective call — R4-F13), structured voice instructions (keyboard-reorderable), few-shot selection.
- **Security envelope:** CSRF (fail-closed on both-signals-absent) on every AI route AND the corpus-ingestion route; atomic DB-backed spend breaker + per-window rate limiter (both 429 before any Anthropic call OR outbound fetch); SSRF defense via app-side hardened fetch passing HTML to `extractFromHtml` (never `extract({url})`), connection-pinning vs DNS rebinding, plus a hardened-fetch contract (AbortController read timeout + STREAMING max-bytes cap + Content-Length early reject — R4-F3); SEO/OG per-field escaping + scheme validation.
- **Cost honesty:** prompt cache defaults to `ttl: '5m'` (R4-F7); per-action cost derived from `max_tokens` output + measured typical thinking, labelled a typical estimate, with the per-action MAX stated in ADR-010.

## 7. Security Posture (write/render boundary)

- **Write-validation cannot be the only gate.** The generic `/api/admin/settings` endpoint is a bypass door: ticker hrefs and author bios are therefore validated/sanitized at **RENDER time**, not only on write (R1-F2). Ticker hrefs use a dedicated LINK-href validator allowing `mailto:`/`tel:`/`https:`/site-relative (NOT `IMAGE_SCHEME_REGEX`, R3-F4). Author bios render through DOMPurify `STRICT_CONFIG`.
- **CSRF reality.** `/api/admin/settings` has NO Origin/Sec-Fetch check today — Phase 6 adds one (R2-F1). No `admin_settings` write path exists anywhere — Phase 7 BUILDS a new authenticated + CSRF + encrypt-on-write endpoint (R2-F2). The inherited `content.ts` CSRF check fails OPEN when both Origin and Sec-Fetch-Site are absent — AI spend/ingestion routes use a STRICTER fail-closed posture (R3-F6).
- **Status visibility hardened at storage.** Phase 2 adds `CHECK (status IN ('draft','published','scheduled','archived'))` on `content.status` (R4-F2) — defense-in-depth behind the exact-match published read filter.
- **Forgeable inputs labelled.** Phase-5 view counts are constrained to published slugs and labelled best-effort/forgeable; `page_path` is rendered only via Astro auto-escaping (R3-F3).

## 9. SEO & Discoverability

- **Categories** are PATH-routed `/blog/category/[slug]` (never query params — R4-F15), indexable above a ≥2-member threshold; below threshold they emit `noindex, follow` and self-canonical to their own path (R1-F31). **Tags** are a non-indexed click-filter (`noindex`, absent from sitemap — R1-F21).
- **Robots third state.** `resolveSeoMetadata` emits `noindex, follow` driving BOTH the `robots` tag (`Layout.astro:65`) AND the hardcoded `googlebot` tag (`Layout.astro:66`, today unconditionally `noindex, nofollow`) from the same state (R2-F22/R3-F17). The INVERSE invariant: pre-existing hard-noindex pages keep `noindex, nofollow` byte-unchanged on both tags (R4-F16).
- **Pagination:** `/blog/page/[n]` generates `n≥2` only; `/blog/page/1` 301s to `/blog`; each `n≥2` page self-canonicals (R3-F19). Page size pinned ≥10 so the 6-post corpus never paginates (R4-F10).
- **JSON-LD Article** via `JSON.stringify` (never `escapeXml`, R1-F29), with `datePublished`/`dateModified`/`author`/`publisher`, an `image` when the post has a featured image, and a `headline` ≤110 chars from `post.title`/clamped (NOT the 160-cap `seoTitle`, R4-F17).
- **RSS 2.0** at `/blog/rss.xml` with RFC-822 dates + atom self-link (R1-F30); 20 most recent published posts; auto-discoverable `<link rel="alternate">` in `<head>`.
- **Sitemap** targets the REAL dynamic blog sitemap (the static one excludes `/blog/*`, R1-F28); each taxonomy/pagination route appears exactly once; no `noindex` page listed; `/blog/page/1` not separately listed.

## 10. Caching

- The blog COLLECTION caches at 5 min (`DEFAULT_COLLECTION_TTL`, `content.ts:28`). The scheduled-publish cron flips `status` only and does NOT invalidate cross-process cache — visibility lag is the 5-min TTL (R1-F16). The cron cadence is every 5 minutes so by-design lag never produces a visibly-overdue post (R3-F12).
- The `settings` table caches at 30 min (`SETTINGS_TTL`, `content.ts:29`) — 6× the blog invariant. The ticker (`ticker_items`/`ticker_enabled`) and virtual authors (`blog_authors`/`blog_virtual_authors`) live there. **Resolution (default):** a dedicated 5-min TTL read path for those keys (a `getCollectionTtl`-style special case or a thin short-TTL read), so the new ticker beside AnnouncementBar (which reads ANNOUNCEMENTS at 5 min) is not 6× staler (R4-F11).
